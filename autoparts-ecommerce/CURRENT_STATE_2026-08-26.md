# Текущее состояние автоматизации — 26.08.2026

Этот документ — точка входа для продолжения работы. Он фиксирует фактически
используемые процессы, последние решения и ограничения. Секреты здесь намеренно
не указаны: локальные значения должны храниться только в `.env` или в отдельно
защищённом файле вне репозитория.

## Маркетплейсы и модель работы

- Магазин на Ozon и Wildberries называется **Continent**.
- Ozon: схема FBS, артикул продавца формируется как `<артикул>-con`.
- Wildberries: схема FBS.
- Основные источники закупки и остатков: **Микадо** и **Автолига**.
- Если товар достоверно не найден в актуальных прайсах, активный остаток должен
  быть равен нулю. Неоднозначные совпадения нельзя угадывать.

## Ozon: цены «Оптимум»

Рабочая градация целевой прибыли относительно закупки и прочих расходов:

| Закупочная цена | Целевая наценка |
|---:|---:|
| менее 500 ₽ | 25% |
| 500–1 199,99 ₽ | 20% |
| 1 200–2 499,99 ₽ | 17% |
| 2 500–3 499,99 ₽ | 15% |
| от 3 500 ₽ | 12% |

Одинаковые пороги записаны в:

- `scripts/price_recalc.py`;
- `../ifoam-ecommerce/ozon_calculator.html`.

Расчёт учитывает комиссию Ozon, эквайринг, логистику FBS, ожидаемые возвраты,
УСН и упаковку. `--force-decrease` разрешает контролируемое снижение при разовом
пересчёте. Обычный плановый режим сохраняет защиту от автоматического снижения.

## Ozon: остатки

`scripts/ozon_stock_sync.py` строит полный план остатков по обоим поставщикам.
Ключевые правила:

1. Загружаются Микадо и последний допустимый прайс Автолиги.
2. Артикул нормализуется только для сопоставления; в API отправляется исходный
   `offer_id`.
3. При неоднозначном артикуле обязательно проверяется бренд.
4. При наличии у обоих поставщиков остатки суммируются, но витринное количество
   ограничивается четырьмя единицами.
5. Перед массовой записью проверяется полнота каталога и создаётся локальный
   аудит плана.
6. Сбой или устаревание обязательного источника отменяет весь цикл, чтобы не
   произвести ошибочное массовое обнуление.

## Изображения

Основной генератор — `scripts/photo_processor.py`.

- `_info` — основное изображение товара.
- `_compat` — дополнительное изображение с применяемостью.
- Памятка о VIN добавляется третьим изображением.
- Памятка о добавлении магазина Continent в избранное — четвёртым/последним
  изображением в зависимости от площадки и состава карточки.
- Длинные артикулы автоматически получают уменьшенный шрифт.
- Для квадратных и вертикальных исходников сохраняется полноценная верхняя зона
  с логотипом и названием.
- Отдельные товарные изображения могут требовать ручного поворота или замены
  исходника; готовый файл должен заменять предыдущую версию без создания
  неуправляемых дублей.

## Карточки товаров

Нормализованные данные раскладываются по специализированным полям, а не
смешиваются в описании:

- название;
- бренд;
- OEM;
- альтернативные артикулы без названий производителей;
- параметры;
- применяемость;
- длина, ширина, высота и вес упаковки;
- описание;
- изображения.

Названия должны быть читаемыми, без необоснованного CAPS, обрывов, хвостовых
запятых и сокращений, теряющих смысл. OEM нельзя смешивать с артикулами другой
детали. Применяемость и совместимость требуют проверки по VIN.

## Безопасность и восстановление

- `.env`, токены, пароли, браузерные профили, логи и оперативные выгрузки не
  коммитятся.
- Прайсы и Excel-результаты могут содержать коммерческие данные и обычно
  хранятся локально; в Git попадают код, схемы и обезличенная документация.
- Перед крупным объединением изменений создаётся отдельный Git-коммит.
- Нельзя автоматически выбирать цену или остаток при конфликтующем артикуле.
- Старые реальные секреты могли существовать в ранней истории репозитория;
  действующие ключи необходимо периодически менять.

## Быстрые проверки

```powershell
# Синтаксис основного кода
python -m compileall autoparts-ecommerce/scripts

# Предварительный расчёт цен без записи
python autoparts-ecommerce/scripts/price_recalc.py --dry-run --force-decrease

# Предварительный расчёт остатков без записи
python autoparts-ecommerce/scripts/ozon_stock_sync.py --dry-run
```

Перед любым реальным массовым обновлением сначала анализируется dry-run и число
пропущенных/неоднозначных позиций.
